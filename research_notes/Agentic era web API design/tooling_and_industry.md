## 1. SDK/doc generators and their agent pivot (Stainless, Speakeasy/Gram, Fern, liblab, APIMatic, Mintlify, ReadMe, Redocly, Scalar, Bump.sh)

### Takeaway
Between November 2025 and September 2026 the SDK-generator category consolidated sharply. Postman bought liblab (Nov 2025) and Fern (Jan 2026). Anthropic bought Stainless (18 May 2026) and shut down its hosted generator. That shutdown pushed the market toward open source: Google partnered with Speakeasy to open-source Speakeasy's generator suite (17 Sep 2026), and Cloudflare released Forge (late Sep 2026). Across the surviving vendors, the standard bundle from one OpenAPI spec is now SDKs + CLI + MCP server + llms.txt/Markdown docs + a hosted docs-search MCP endpoint. "Agent-ready docs" is now table stakes, not a differentiator.

### Inferences
- The SDK-generator market split three ways. **Postman** (Fern + liblab) is building an integrated lifecycle suite. **Speakeasy** is independent, Google-aligned and now open-source-leaning. **Cloudflare Forge** and OpenAPI Generator/Kiota cover the self-hosted open-source end. A frontier AI lab owning Stainless made "vendor risk in codegen" a live concern; Google's blog states that rationale explicitly.
- A de facto "agent-ready API surface" checklist has emerged across vendors: (1) `llms.txt` + `llms-full.txt`; (2) per-page Markdown (`.md` suffix and/or `Accept: text/markdown`); (3) a hosted docs-search MCP endpoint; (4) an OpenAPI→MCP tool server with opt-in endpoint selection; (5) generated CLIs and agent "skills" files; (6) discovery cards (MCP server card, A2A agent card).
- Vendors are moving away from naive "one tool per endpoint" generation (Stainless code-exec + docs-search, Cloudflare Code Mode, Speakeasy curated toolsets, Mintlify opt-in endpoints). Tool curation and token budgeting are now core design problems.

### Gaps
- No primary Stainless or TechCrunch page could be read. The shutdown effective date (18 vs 19 May) and the migration timeline are unconfirmed.
- The exact release date of Cloudflare Forge (21 vs ~28 Sep 2026) is unconfirmed. The licensing of the Google/Speakeasy open-source suite and its timeline, and whether it includes Speakeasy's MCP/Gram targets, were not confirmed.
- No GA date was found for Gram. Speakeasy's funding totals conflict.
- No usage data was found on how often agents actually consume llms.txt or docs-MCP endpoints (vendor or independent).
- liblab's product fate inside Postman, and whether Fern and liblab will be merged, are unknown.

## 2. API gateways and API management as AI/MCP gateways (and related M&A)

### Takeaway
By October 2026 every major API management vendor has shipped some combination of: (a) exposing existing REST APIs as MCP tools at the gateway; (b) proxying and governing third-party MCP servers (OAuth 2.1 resource server, per-tool ACLs, tool filtering); (c) LLM-traffic controls (token rate limits, cost metering, semantic caching, guardrails); and increasingly (d) A2A proxying. Maturity varies: AWS AgentCore (GA Oct 2025), Kong (Agent Gateway Apr 2026) and Apigee API hub MCP (GA Jul 2026) are GA. Azure APIM's MCP support was last confirmed as preview, and Zuplo's MCP Gateway is in beta. Security vendors and iPaaS players are buying AI-gateway startups (Palo Alto–Portkey, Boomi–Lunar.dev).

## 3. API design-first and governance tooling: state of the art, including AI-specific linting

### Takeaway
The classic design-first toolchain is still the backbone and has not been replaced by AI. That chain is: linting (Spectral rulesets, increasingly run by the faster Go-based **vacuum**), Redocly CLI, breaking-change detection (**oasdiff**), mocking (Prism, **Microcks**, now CNCF Incubating as of May 2026), contract testing (Pact/PactFlow) and property-based testing (Schemathesis), plus **TypeSpec** (1.0 GA) as an API-first DSL. What changed in 2025–26: (1) these tools now ship their own MCP servers and agent skills so coding agents can drive them; (2) a new category of "AI-readiness" scoring for OpenAPI appeared (Jentic's scorecard, `agent-ready`), but there is no standard ruleset; (3) catalogs like Backstage, Apigee API hub and Azure API Center doubled as MCP/tool registries.

### Cited Findings

**Linting**
- **Spectral** (Stoplight, now SmartBear) is still the de facto ruleset format. A Feb 2026 Speakeasy post (a competitor) says Spectral has had "little investment since SmartBear acquired Stoplight," pulls in Node.js, and slows down on large specs. The same post calls **vacuum** fast and Go-native but noticeably more memory-hungry. Speakeasy explains why it built its own linter. — [Speakeasy blog](https://www.speakeasy.com/blog/why-we-built-our-own-openapi-linter)
- **vacuum** (Dave Shanley / quobix) is compatible with Spectral rulesets and report formats. It supports OpenAPI 2/3, AsyncAPI and JSON Schema, and has a dashboard and HTML reports. It claims to lint a 5 MB spec in ~230 ms (self-reported). The latest version seen is v0.99.11 (15 Jul 2026, from a pkg.go.dev mirror path). — [pkg.go.dev](https://pkg.go.dev/github.com/justinclift-prvidr/vacuum); [MacPorts](https://ports.macports.org/api/v1/ports/vacuum/); [pkg.go.dev (perf claim)](https://pkg.go.dev/github.com/daveshanley/vacuum@v0.0.27)
- **Zally** (Zalando) is a configurable OpenAPI 2/3 linter. It has no agent-specific rules out of the box. — [API Evangelist](https://providers.apievangelist.com/providers/zally/)

**AI/agent-readiness scoring (new category; no standard)**
- **Jentic API AI-Readiness Scorecard** is a free CLI that scores any OpenAPI document across dimensions including structural validity, documentation quality, semantic clarity, security and **AI discoverability**, producing a weighted grade. Linter results feed in as one signal. Jentic says the framework was developed with input from senior OpenAPI Initiative members. It ships as a Claude Code agent skill. Jentic's pitch: you can run Spectral, pass everything, "and yet your AI agent still fails to use the API reliably." — [Jentic blog](https://www.jentic.com/blog/agent-check-if-your-apis-are-ai-ready); [Compare the Cloud](https://www.comparethecloud.net/news/jentic-launches-free-api-scoring-tool-to-measure-readiness-for-ai-agent-integration)

- **`openapi-agent-ready` (PyPI v0.3.0)** audits OpenAPI for agent and MCP readiness across 7 failure categories (e.g., Description Clarity, Auth Clarity, Parameter Explanation), can gate CI, and scaffolds an MCP server. — [PyPI](https://pypi.org/project/openapi-agent-ready/0.3.0/)
- Doc-level agent-readiness audits also exist: Mintlify's site score checks llms.txt, Markdown content negotiation and similar. ### Inferences

## 4. MCP registries, marketplaces and enterprise MCP management

### Takeaway
A layered registry model has emerged. At the top is the **official MCP Registry** (preview since 8 Sep 2025, API frozen at v0.1 since Oct 2025, still "preview" as of mid-2026), which acts as the upstream metadata source. Public and private **sub-registries** sit beneath it: GitHub's registry and allowlist controls, the Docker MCP Catalog, Kong MCP Registry, Azure API Center, Apigee API hub, MuleSoft Agent Registry, and Smithery/Glama marketplaces. **MCP gateways** handle runtime enforcement (Docker MCP Gateway, Cloudflare portals, Speakeasy, Kong, Zuplo, agentgateway, ContextForge). Registry-based allowlists alone are weak controls, and practitioners argue enforcement must happen at the client or gateway.

### Cited Findings
- The **official MCP Registry launched in preview on 8 Sep 2025** at `registry.modelcontextprotocol.io`. It is open source, with a parent OpenAPI spec so anyone can build compatible **sub-registries** (public ones that enrich upstream data; private enterprise ones). It warns of possible breaking changes and data resets before GA and does not cryptographically validate server payloads. — [MCP blog](https://blog.modelcontextprotocol.io/posts/2025-09-08-mcp-registry-preview/)
- The Registry API was **frozen at v0.1 on 24 Oct 2025** to gather feedback for v1 GA. As of Jul 2026 it was still "formally a preview." — [modelcontextprotocol.info](https://modelcontextprotocol.info/tools/registry/); [Towards AI, mid-2026](https://pub.towardsai.net/mcp-registries-in-mid-2026-one-upstream-won-2ce541b92036)
- Registry size snapshots (third-party, and counting methods differ): **24,240 distinct servers from 79,341 version records (22 Aug 2026)**; **26,479 total servers (2 Sep 2026 snapshot)**; "10,000 public servers" milestone (Apr 2026). — [jwatte.com](https://jwatte.com/blog/mcp-servers-for-small-business.md); [Daily AI World](https://dailyaiworld.com/blogs/mcp-registry-26479-servers-alive-health); [AgentMarketCap](https://agentmarketcap.ai/blog/2026/04/17/mcp-10000-public-servers-ecosystem-milestone)
- **GitHub:** internal MCP registry and allowlist controls arrived in VS Code Insiders on 12 Sep 2025 and **VS Code Stable public preview on 18 Nov 2025**. Admins set a registry URL and choose "Allow all" (discovery) or "Registry only" (allowlist). Visual Studio has discovery only. — [GitHub changelog (Sep 2025)](https://github.blog/changelog/2025-09-12-internal-mcp-registry-and-allowlist-controls-for-vs-code-insiders/); [GitHub changelog (Nov 2025)](https://github.blog/changelog/2025-11-18-internal-mcp-registry-and-allowlist-controls-for-vs-code-stable-in-public-preview/); [GitHub docs](https://docs.github.com/en/enterprise-cloud@latest/copilot/how-tos/administer-copilot/manage-mcp-usage/restrict-based-on-registry)
- The GitHub MCP Registry is a curated directory (Sep 2025) with one-click VS Code install, fed from the official registry (secondary source). — [Speakeasy resource](https://www.speakeasy.com/resources/mcp-registry)
- One analysis notes that GitHub's registry-only policy matches on server name or ID and "can be bypassed by editing configuration files." It argues registries are catalogues, not controls, and that enforcement belongs at the client or gateway (opinion). — [Beri.net](https://www.beri.net/article/mcp-server-governance-allowlist-registry-gateway-buyers-guide)
- **Docker MCP Catalog & Toolkit:** 300+ "verified" servers (docs accessed Sep 2026; 100+ at the Apr 2025 launch) packaged as signed/versioned container images. "Profiles" mix catalog and remote servers, and orgs can build custom catalogs. The open-source **MCP Gateway** routes requests, manages credentials, starts and stops servers, and enforces access. Docker says "verified" means its own catalog process, not a safety guarantee. — [Docker docs](https://docs.docker.com/ai/mcp-catalog-and-toolkit.md); [InfoQ](https://www.infoq.com/news/2025/04/docker-mcp-catalog-toolkit)
- **Kong MCP Registry** (Konnect Catalog, 2 Feb 2026); **Azure API Center → Foundry private tool catalog** (public preview); **Apigee API hub MCP server** (GA 24 Jul 2026); **MuleSoft Agent Registry** with public MCP assets: see §2.
- **Smithery:** an MCP marketplace and hosting service. A directory lists a 1 Feb 2026 investor entry (Hawk Hill), amount unknown. In Jun 2025 a path-traversal vulnerability reportedly exposed 3,000+ hosted MCP servers and API keys; it was fixed within 48h (secondary source). — [Parsers.vc](https://o.parsers.vc/startup/smithery.ai/); [Stork.ai](https://www.stork.ai/es/smithery)
- **Glama** argued in Jan 2026 that MCP is "not dead" after a hype peak in mid-2025 (vendor narrative, not Gartner). — [Glama blog](https://glama.ai/blog/2026-01-20-mcp-is-not-dead)
- **Postman** launched a "network for MCP servers" where publishers host discoverable tools. — [SD Times](https://sdtimes.com/api/postman-releases-several-new-capabilities-at-its-annual-user-conference/)
- **MCP gateway / observability products:** Speakeasy MCP Gateway (Mar 2026), Cloudflare MCP portals plus Code Mode, Zuplo MCP Gateway (beta), Kong AI MCP Proxy, Gravitee MCP Proxy with tool quarantine and MCP dashboards, agentgateway (AAIF), IBM ContextForge, TrueFoundry (MCP metrics), Akto (Jul 2026 MCP gateway release with guardrails for Claude Cowork and Kiro CLI). — [Gravitee MCP monitoring](https://documentation.gravitee.io/agent-management/observe/dashboards/monitor-your-mcp-servers); [TrueFoundry docs](https://www.truefoundry.com/docs/ai-gateway/analytics-mcp-metrics); [Akto](https://www.akto.io/blog/mcp-gateway)
- TrueFoundry says Gartner's *Innovation Insight: MCP Gateways* (2025) named it an emerging provider, and attributes to Gartner the figure of 16,000+ MCP servers deployed in 2025 (both vendor claims about Gartner). — [TrueFoundry](https://www.truefoundry.com/blog/truefoundry-and-the-mcp-gateway-revolution-insights-from-gartners-2025-report)

### Inferences
- "One upstream won." The official registry is the metadata spine and everything else is a sub-registry or curation layer. Its long preview with a v0.1 API freeze means enterprises still depend on vendor registries (GitHub, Docker, Kong, Azure, Apigee, MuleSoft) for trust signals.
- Enterprise MCP management now has three parts: **catalog/registry (discovery + approval) → gateway (auth, ACL, filtering, quarantine, audit) → client policy (allowlist enforcement)**. No single product covers all three across vendors.
- Registry counts are noisy (version records vs. distinct servers vs. live servers) and should be cited with methodology.

- No primary GitHub announcement for the public GitHub MCP Registry launch was retrieved.
- No funding or traffic data was found for Glama, and none was confirmed for Smithery.
- No independent data was found on the share of enterprise MCP usage going through gateways versus direct connections. Tyk's "90% local" claim is unverified.

No FedRAMP/HIPAA. — [Scalekit](https://www.scalekit.com/blog/atlassian-mcp-vs-api); [Jimi Wikman (release note mirror)](https://jimiwikman.se/atlassian/atlassian-resources/atlassian-app-updates/atlassian-rovo-mcp-server-is-now-generally-available-r484/); [Atlassian developer docs](https://developer.atlassian.com/cloud/rovo-mcp/guides/authentication-and-authorization/); [Atlassian](https://www.atlassian.com/platform/remote-mcp-server)
- **Notion:** a hosted MCP server at `mcp.notion.com/mcp` with OAuth. Tools return **"Notion-flavored Markdown" designed for agents**. The local OSS server is de-prioritized and may be deprecated. — [Stacklok ToolHive](https://docs.stacklok.com/toolhive/guides-mcp/notion-remote); [Notion developers](https://developers.notion.com/docs/hosting-a-local-mcp-server)
- **Linear:** a centrally hosted, authenticated remote MCP server with tools for issues, projects and comments (secondary source). — [Department of Product](https://departmentofproduct.substack.com/p/how-to-develop-an-mcp-product-strategy)
- **Salesforce:** hosted MCP servers reportedly **GA in Apr 2026 (one source: 29 Apr)** for Enterprise Edition and above. They use OAuth 2.0 + PKCE inside Salesforce's perimeter, and **every request runs with the calling user's permissions**. The Agentforce MCP *client* status conflicts (launched with Agentforce 3 in Jun 2025 vs. beta since Jan 2026). — [Truto](https://truto.one/blog/best-mcp-server-for-salesforce-hosted-mcp-vs-unified-api-2026/); [Atlan](https://atlan.com/know/ai-agent/mcp-server-for-salesforce/); [Peliqan](https://peliqan.io/blog/agentforce-mcp-vs-peliqan/)
- **PayPal:** Agent Toolkit plus MCP server (`@paypal/mcp`, plus a remote server) covering orders, invoices, subscriptions, shipment tracking, transactions and disputes. — [PayPal developer blog](https://developer.paypal.com/community/blog/paypal-agentic-ai-toolkit/); [PayPal Agent Toolkit docs](https://paypal.gitbook.com/agent-toolkit-and-mcp-server)
- **Twilio:** a hosted **read-only docs MCP** at `mcp.twilio.com/docs` indexes all public Twilio OpenAPI specs plus Twilio, SendGrid and Segment docs. It needs no account and exposes two tools (`twilio__search`, `twilio__retrieve`) but does not execute calls. A separate execution-capable **alpha** package (`@twilio-alpha/mcp`) uses account credentials. Twilio warns against running community MCP servers alongside the official ones. — [Twilio docs](https://www.twilio.com/docs/mcp); [Twilio blog](https://twilio.com/en-us/blog/introducing-twilio-alpha-mcp-server); [Glama listing](https://glama.ai/mcp/servers/r5bf5ljhvm)
- **Zapier MCP:** included in all plans. Each successful tool call costs **2 tasks** and failed calls are free, so a 20-step agent job costs 40 tasks. Reach is variously given as 8,000 or 9,000+ apps and 30,000+ actions (third-party sources). — [Latenode](https://latenode.com/blog/zapier-mcp-pricing); [Ry Walker](https://rywalker.com/research/zapier-mcp)
- **Cloudflare** as exemplar: collapsing a 2,500-endpoint API into two Code Mode tools (~1,000 tokens) is the most-cited answer to "large API → agent" (see §2). — [Cloudflare changelog](https://developers.cloudflare.com/changelog/post/2026-03-26-mcp-portal-code-mode/)

### Inferences
- These offerings fall into six recurring patterns:
  1. Remote, vendor-hosted MCP with OAuth 2.1 instead of local servers.
  2. Agent permissions bounded by the human user's permissions or restricted keys.
  3. Separate docs/search MCP (safe, unauthenticated) from execution MCP (credentialed).
  4. Curated, consolidated toolsets instead of 1:1 endpoint mapping (GitHub consolidation, Stripe "not exhaustive," Cloudflare Code Mode).
  5. Agent-optimized response formats (Notion-flavored Markdown).
  6. Admin controls: allowlists of AI clients, IP allowlists, rate limits per plan.
- Commerce companies add a protocol layer (ACP/UCP/MPP/x402) on top of MCP. "Agentic commerce" is the most commercially mature agent-API vertical in 2026.

### Gaps
- The widely circulated claim that "70% of Stripe's API commands now come from agents" could not be traced to a Stripe source. Treat it as unverified.
- No official Shopify changelog was read. Shopify dates and tool names come from agency blogs.
- Linear's MCP details rest on a secondary source. Salesforce's GA date comes from third-party blogs.
- Twilio's execution MCP remains "alpha." No GA status was found.

## 6. Market and survey data (Postman, Gartner, Kong, traffic share)

### Takeaway
Survey and analyst data tell a consistent story. A quarter of developers already design APIs for agents (Postman 2025). Gartner's 2026 API Hype Cycle calls AI agents "becoming primary consumers of APIs." Vendor-relayed Gartner predictions put agent consumption of most APIs at 80% of organizations by 2028. Hard measurements of the **agent share of API traffic** (as opposed to web traffic) are almost nonexistent; most available numbers come from bot-management vendors measuring web traffic.

### Cited Findings

**Postman State of the API**
- **2025 report (8 Oct 2025; 5,700+ respondents):** **24.3% of developers design APIs with AI agents in mind**. The top security worry is agents making unauthorized or excessive API calls (**50.8%**), followed by AI systems leaking API credentials (**45.95%**). CEO Abhinav Asthana: APIs are "no longer just powering applications, they're powering AI agents." — [Business Wire](https://www.businesswire.com/news/home/20251008162423/en); [Nordic APIs](https://nordicapis.com/a-deep-dive-into-the-state-of-the-api-2025/)
- 89% of respondents use generative AI tools daily (secondary summary). — [Nordic APIs](https://nordicapis.com/a-deep-dive-into-the-state-of-the-api-2025/)
- **2024 report:** Postman saw a **73% increase in AI-driven API traffic** on its platform year over year (5,600+ respondents). — [Business Wire](https://www.businesswire.com/news/home/20241015081863/en)
- **2026 report:** a page exists at `postman.com/state-of-api/2026`, but no findings were published or captured as of this research. — [Postman](https://postman.com/state-of-api/2026)

**Gartner**
- **Hype Cycle for APIs, 2025 (8 Jul 2025):** the API world is evolving "mostly around AI," and agent protocols are emerging alongside federated gateways. — [Gartner abstract](https://www.gartner.com/en/documents/6694934)
- **Gartner Insights (Aug 2025):** MCP took AI/API developers through "an extreme cycle of hype," and Google's A2A added more. — [Gartner abstract](https://www.gartner.com/en/documents/6881266)
- **Hype Cycle for APIs, 2026 (22 May 2026):** GenAI, MCP and agentic protocols are changing how APIs are created, managed and secured, and **AI agents are becoming primary consumers of APIs**, requiring contextual documentation, federated management and modern portals. Apollo's summary (vendor) places GenAI-driven API generation and consumption near the Peak and describes AI gateways as maturing, alongside federated API management against sprawl and rising API-security-testing pressure. — [Gartner abstract](https://www.gartner.com/en/documents/7898077); [Apollo GraphQL](https://www.apollographql.com/resources/gartner-hype-cycle-for-apis-2026)
- **Hype Cycle for Agentic AI, 2026** places communication protocols (MCP), multi-agent systems and orchestration under "agent integration and deployment." — [OneReach (vendor-hosted)](https://onereach.ai/resources/gartner-2026-hype-cycle-for-agentic-ai/)
- Gartner predictions, all relayed through vendors:
  - **"By 2028, 80% of organizations will see AI agents consume the majority of their APIs."** From Gartner's Aug 2025 "How MCP and the A2A Protocols Impact API Management." — [Salt Security](https://content.salt.security/Gartner-How-MCP-and-the-A2A-Protocols-Impact-API-V2.html)
  - **"By 2026, over 30% of the increase in demand for APIs will come from AI and tools using LLMs."** — [Tyk](https://tyk.io/blog/ai-and-enterprise-workflows-essential-tools-and-trends-that-tip-the-balance/)
  - **"By end of 2026, 75% of API gateway vendors will integrate MCP features"** (a companion figure gives 50% of iPaaS vendors). — [Zuplo](https://zuplo.com/blog/gartner-75-percent-api-gateways-mcp); [Tyk](https://tyk.io/learning-center/why-mcp-gateways-are-the-next-evolution-of-api-management/)
  - **AI gateways:** "by 2028, 70% of [orgs building multi-LLM apps / software engineering teams building multimodel apps] will use AI gateway capabilities." Zuplo gives a 25% baseline for 2025; the wording varies by source. — [Zuplo](https://zuplo.com/blog/gartner-75-percent-api-gateways-mcp)
- **Gartner MQ for API Management 2026:** see §2 (published 28 Sep 2026; 17 vendors).

**Kong**
- **API Impact Report 2024:** 83% of respondents say AI investments produced new products or services in the past year. Secondary sources cite Kong projecting a $17.3T API economic impact by 2030, a 170% rise in the value of AI-enabling APIs, and a 548% rise in API attacks by 2030 (unverified against the original). — [Kong](https://konghq.com/resources/reports/ai-and-api-adoption-challenges); [VoxBooster (secondary)](https://voxbooster.com/de/blog/api-economy-statistics-2026/)
- Kong's API Security Perspectives 2025 found 25% of respondents had faced AI-enhanced API/LLM threats (secondary summary). — [Kong reports index](https://konghq.com/resources/reports/page/1)

**Agent traffic measurements (mostly web, not API)**
- **HUMAN Security, 2026 State of AI Traffic report (26 Mar 2026; CY2025 data):** traffic from AI agents and agentic browsers grew **7,851% year over year**. AI-driven traffic grew 187% Jan→Dec 2025, and automated traffic grew ~8x faster than human traffic (23.5% vs 3.1%). Over 95% of AI-driven traffic went to retail/e-commerce, streaming/media and travel. — [HUMAN press release](https://www.humansecurity.com/newsroom/2026-state-of-ai-traffic-cyberthreat-benchmark-report/); [HUMAN report PDF](https://www.humansecurity.com/wp-content/uploads/HUMAN_Report_2026-State-of-AI-Traffic-and-Cyberthreat-Benchmark.pdf)

- **Cloudflare Radar** (as relayed): automated requests were 57.5% of HTML web traffic versus 42.5% human. — [WorkOS](https://workos.com/blog/ai-agent-web-traffic-what-developers-need-to-change)
- HUMAN's monthly "State of Agentic Traffic" series continued through Aug 2026 (e.g., Aug 2026: agentic traffic +27% to a new high, with a strong Codex debut). — [HUMAN blog, Aug 2026](https://www.humansecurity.com/learn/blog/state-of-agentic-traffic-august-2026-agentic-traffic-grows-27-reaches-new-high-as-codex-debuts-strongly/)

**Adjacent adoption signals**
- **llms.txt adoption:** 8.7% of the top 1,000 websites publish llms.txt as of Jun 2026, up from ~0.3% in Jun 2025. Tech sites lead at ~36%. This is a single-vendor tracker. — [Rankability](https://www.rankability.com/blog/llms-txt-adoption/)
- **Funding and M&A signals (2025–26):** Mintlify ($45M B, $500M valuation), Stainless (~$150M valuation in Dec 2025, then $300M+ exit), Portkey and Lunar.dev exits, Postman's two acquisitions, Kong–OpenMeter, Gravitee–Ambassador, and Salesforce–Informatica ($8B). See §1–2.

### Inferences
- Analyst framing moved within one year from "MCP hype" (Aug 2025) to "agents are primary API consumers" (May 2026). Vendors now cite Gartner's 2028 "80% of orgs" prediction as the headline justification for MCP and AI-gateway investment, but the primary text was not verifiable here.
- The best evidence of agent API usage is indirect: Postman's platform AI-traffic growth (+73% in 2024), web bot and agent traffic growth (HUMAN, DataDome), and vendor M&A intensity. A credible, cross-industry "agent share of API calls" figure does not yet exist.

### Gaps
- No 2025 or 2026 Kong API Impact Report was found. Only the 2024 edition was confirmed.
- No apidays industry report data (e.g., "State of API" or "API landscape" 2025/26) was found.
- Gartner primary texts are paywalled. The exact Hype Cycle phase placements of MCP, AI gateways and A2A, and the exact wording of the 2028 predictions, were not verified against Gartner.
- No independent measurement of agent share of *API* (rather than web) traffic was found. The "70% of Stripe API commands from agents" claim is unsourced.
- The Postman 2026 State of the API findings were not yet available or captured. If released in Oct 2026, they should be checked before final publication.
- The web search budget ran out at the end of this research. Follow-up searches on Gartner primary texts and the Postman 2026 report were not possible.
